# AOF v11.0 Release Definition

## Theme

Read-first GitHub Provider Observation Proof.

## What You Can Do Now

AOF can now inspect the real GitHub repository state in read-only mode and select the next most important task with Japanese, evidence-backed, operator-readable reasoning.

Before v11.0, AOF could govern provider readiness internally, but the operator still had to ask whether AOF could look at an actual GitHub context and turn that context into a concrete next task.

After v11.0, AOF has a bounded proof chain for this question: read GitHub metadata, open issues, open PRs, latest release, and recent Actions runs; compare them with local roadmap/runtime state; produce candidate tasks; select one task; and state Go/No-Go with explicit no-write boundaries.

## Contract

GitHub read-only observation is valid only when:

- `permission_boundary.mode` is `read_only`
- allowed operations contain only reads
- issue creation, pull request creation, push, secret access, and external writes are explicitly not authorized
- candidate tasks are recorded in Japanese
- one selected task has evidence, Go/No-Go, and human next action
- candidate evidence refs resolve
- latest release and recent Actions evidence are recorded
- not-proven boundaries remain explicit
- `github-readonly-observation-audit` passes
- `release-state-audit` includes this gate for v11.0 and later

## User-Visible Example

```text
最重要タスクは「GitHubを読み取って、AOFが本当に次の仕事を判断できるか試す」です。
理由は、open issue / open PR が0件で、最新releaseはv10.9.0、roadmap上の次frontierがv11.0だからです。
Goです。ただしGitHub書き込み、Issue/PR作成、push、secret参照は不可です。
```

## Not Proven

v11.0 proves only a read-only GitHub observation and task-selection contract. It does not prove GitHub writes, issue or PR creation, credential safety, external provider execution, semantic truth, productivity improvement, third-party adoption, or market value.
