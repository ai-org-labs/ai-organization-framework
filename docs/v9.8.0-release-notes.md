# AOF v9.8.0 Release Notes

## What You Can Do Now

AOF can now present provider readiness as one production go/no-go evidence candidate.

Instead of manually reading separate approval, target, reproduction, rollback, outcome, learning, incident, cost/quota, and product-value artifacts, an operator can inspect a bounded release surface that says whether the chain is ready for production go/no-go review.

This is not live provider execution permission.

## Capability Delta

NEW:

- `PCAP-PRODUCTION-GONOGO`: AOF can bundle provider readiness evidence into a production go/no-go candidate.

UPDATED:

- `PCAP-PROVIDER-EXECUTION`: readiness is now exposed as a candidate for operator judgment, not only as separate audit outputs.
- `PCAP-PRODUCT-VALUE-COMPREHENSION`: production movement must be explained by user-facing capability and not-proven boundaries.

REMOVED:

- None.

## Capability Matrix

See [AOF Capability Matrix](aof-capability-matrix.md).

| Capability | v9.7 | v9.8 |
|---|---|---|
| Production Go/No-Go Evidence | Not present | One bounded candidate surface for production readiness judgment |
| Provider Execution | Separate readiness evidence chain | Approval, target, reproduction, rollback, outcome, incident, cost/quota, and value evidence connected for go/no-go review |
| Product Value Comprehension | Provider baseline explained as lifecycle traceability capability | Production movement explained as user-facing judgment capability with explicit not-proven boundary |

## Before / After

Before v9.8, AOF had the upstream records needed for provider readiness, but an operator still had to mentally assemble the production-readiness chain.

After v9.8, AOF exposes the chain as a release-grade production go/no-go evidence candidate while keeping live execution unauthorized.
