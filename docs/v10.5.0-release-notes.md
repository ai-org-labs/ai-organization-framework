# AOF v10.5.0 Release Notes

## What You Can Do Now

v10.5 gives AOF a provider-backed work lifecycle product surface. An operator can now see how a Need becomes governed work, where a provider candidate enters, which authorization and evidence gates apply, who reviews the state, what is blocked, and what should happen next.

This is not live provider execution. It is the user-facing lifecycle explanation needed before provider-backed work can become a credible product workflow.

## Capability Delta

NEW:

- `PCAP-PROVIDER-BACKED-WORK-LIFECYCLE-SURFACE`: explain provider-backed work as a user-facing lifecycle from Need to blocked/ready next action.

UPDATED:

- `PCAP-EXTERNAL-VALUE-REPRODUCTION-PACKAGE`: external reviewers can use the lifecycle surface as scenario context.
- `PCAP-EXTERNAL-PROVIDER-PILOT-SELECTION`: selected provider pilot now appears in the lifecycle story.
- `PCAP-PRODUCTION-EXECUTION-AUTHORIZATION-MODEL`: authorization gates are positioned inside the lifecycle.

REMOVED:

- None.

## Capability Matrix

See `docs/aof-capability-matrix.md` for the version-by-capability table.

## Before / After

Before v10.5, AOF had provider selection, authorization gates, and external reproduction package, but they were separate proof surfaces.

After v10.5, AOF can tell the provider-backed work story as one lifecycle: need, validation, planning, provider candidate, authorization, evidence, Council review, blocker, and next action.

## Five-Minute Demo

1. Read `docs/v10.5-release-definition.md`.
2. Check the Lifecycle Surface Contract section.
3. Run `node ./src/cli.js release-state-audit --project .`.
4. Confirm v10.5 does not claim live provider execution, provider write safety, or production safety.

## Value Evidence

- Operators no longer need to stitch separate provider-readiness docs together manually.
- AOF presents provider-backed work as a product workflow instead of an artifact pile.
- External reviewers get a clearer story for future value reproduction.

## Not Proven

v10.5 does not prove live provider execution, provider write safety, production safety, completed provider integration, external adoption, market value, or third-party validation completion.
