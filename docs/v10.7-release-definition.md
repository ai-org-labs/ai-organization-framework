# AOF v10.7 Release Definition

## Theme

Capability Coverage Gate.

## User Capability

AOF can now stop release-critical or build-like work before implementation when required expertise is only nominally present. A role being defined in the organization is no longer enough: required roles and skills must be connected to concrete actor skill packets, assignment evaluations, execution gates, expected outputs, acceptance gates, and Council review evidence.

## Why This Release Exists

External project feedback showed a real failure mode: AOF could let a build proceed when game design, UX, level design, or player QA expertise was not actually assigned to the work. That made AOF overtrust organization shape and undercheck execution coverage.

## Contract

For scoped work at or after TASK-127, capability-coverage-audit verifies:

- work item goal declares required roles, required skills, expected outputs, success criteria, and go/no-go gates
- required roles exist and are assigned through actor skill packets
- required skills exist and are packet-covered by concrete actors
- actor assignment evaluations are selected before execution
- actor execution gates are allowed before build
- Council review exists
- Council review cannot mention missing role, missing skill, player comprehension risk, required validation, or recommended next step without follow_up_task_ids
- all coverage refs resolve

## Release-State Integration

release-state-audit includes capability-coverage-audit for v10.7.0 and later.

## Not Proven

This release proves structural and runtime coverage gating. It does not prove that selected actors are semantically perfect experts, that a product will succeed, or that human playtest/UX truth has already been validated.
