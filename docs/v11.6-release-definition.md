# AOF v11.6 Release Definition

## Release

- Version: `11.6.0`
- Theme: External Operator Reproduction Feedback Intake
- Work item: `TASK-137`

## Capability First

After v11.6, AOF can record whether an external operator understood, reproduced, rejected, or was confused by a provider observation replay.

This changes provider-read validation from "AOF says the replay exists" to "AOF records whether a human-facing operator could actually use the replay, and routes weak feedback into product governance."

## Capability Matrix

| Capability | v11.5 | v11.6 |
|---|---:|---:|
| GitHub read-only observation | Yes | Yes |
| Provider read integration | Yes | Yes |
| External validation replay | Yes | Yes |
| Human-readable provider observation replay | Yes | Yes |
| External operator reproduction feedback intake | No | Yes |

## Release Gates

- `external-operator-feedback-audit` passes.
- Feedback records include operator result, reproduction result, questions, confusing points, governance route, product evidence value, and not-proven boundary.
- Weak feedback cannot silently pass. Partial, confused, rejected, failed, or not-attempted feedback must require product review.
- Rejected or failed feedback cannot be accepted as product evidence.
- Feedback records link to provider observation replay evidence.
- `release-state-audit` includes the v11.6 external-operator-feedback gate.

## Value Evidence

Before v11.6, AOF could make provider evidence human-readable, but it did not formally record whether that explanation landed with an external operator. After v11.6, operator comprehension and reproduction feedback becomes auditable product evidence.

## Not Proven

v11.6 does not prove broad adoption, market value, semantic truth, provider correctness, production automation safety, credential safety, GitHub write safety, or productivity improvement.
