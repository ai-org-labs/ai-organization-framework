# AOF v11.8 Release Definition

## What You Can Do Now

Operators can see whether provider-read evidence is current enough to reuse.

Before v11.8, Mission Control could show a provider-read decision replay, but old provider observations could still look operationally current unless the operator manually checked timestamps and boundaries.

After v11.8, AOF records and audits a provider-read freshness refresh gate before old observations are reused as decision evidence.

## Capability Delta

NEW:

- `PCAP-PROVIDER-READ-FRESHNESS-REFRESH`: AOF can classify provider-read evidence as current, stale, expired, or unknown, then require refresh or block reuse when freshness is insufficient.

UPDATED:

- `PCAP-PROVIDER-READ-DECISION-REPLAY`: decision replay now has an upstream freshness gate for follow-on reuse.

REMOVED:

- None.

## Release Gates

1. `provider-read-freshness-refresh-audit` passes.
2. `release-state-audit` includes the v11.8 provider-read freshness refresh gate.
3. Mission Control includes `provider_read_freshness_refresh_projection`.
4. The v11.8 self-hosting chain includes provider read decision replay, freshness refresh evidence, product value evidence, capability delta, and agent session evidence.
5. Not-proven boundaries remain visible.

## Boundaries

This release proves freshness governance over recorded provider-read evidence only.

It does not prove provider semantic truth, live provider availability, GitHub write safety, credential safety, production automation safety, market value, broad adoption, or productivity improvement.
