# AOF v10.8 Release Definition

## Theme

Role Routing Fail-Closed Runtime.

## What You Can Do Now

AOF can now stop Council execution before planning proceeds when a required specialist role is not backed by a concrete actor.

Before v10.8, a project could register a specialist such as `Game Planner`, but the planning Council could still run with only the default seats. This allowed important domain decisions to be made without the specialist actually participating.

After v10.8, Council execution resolves every required role to an actor before it prepares or persists a run. If `Game Planner`, `UX`, `Level Designer`, `QA`, or any other required role cannot be routed to an actor, execution fails closed and no partial Council run is stored.

## Contract

Council execution must satisfy all of the following before work can proceed:

- every default Council seat resolves to a concrete actor from the project template
- additional required roles supplied by the session or `--required-role` are joined into the Council plan
- role matching is tolerant of spelling format differences such as `game-planner` vs `Game Planner`
- unresolved required roles fail closed before model invocation and before session persistence
- persisted Council execution steps include `actor_ref` so operators can see who performed each role
- deep-path planning includes Visionary, Builder, and Guardian by default

## User-Visible Example

```bash
aof council-exec \
  --session .aof/sessions/<session>.json \
  --stage planning \
  --required-role "Game Planner"
```

If the template contains an actor with `roles: [Game Planner]`, that actor is added as a specialist seat.

If not, AOF stops with:

```text
Role routing failed closed: no actor found for required role 'Game Planner' during planning.
```

## Why This Release Exists

Operator feedback identified a serious runtime gap:

- organization registration and Council execution could diverge
- Planning Council could omit required specialist roles
- a role could be requested but not resolved to an actor
- missing specialist judgment could be discovered only after work had already moved forward

This is not a game implementation issue. It is an AOF organization execution and routing-layer issue.

## Not Proven

This release proves structural runtime routing and fail-closed behavior. It does not prove that the selected specialist is semantically expert, that their recommendation is correct, or that a product decision is market-valid.
