# AOF v11.5 Release Definition

## Release

- Version: `11.5.0`
- Theme: Human-readable Provider Observation Replay
- Work item: `TASK-136`

## Capability First

After v11.5, an operator can inspect one replay packet and understand:

- what external provider state was read
- why that provider state mattered to the release decision
- what changed compared with the prior state
- what remains unproven
- what should happen next

This is not a provider-write release. It is a human-readable replay layer over the existing read-only provider evidence chain.

## Capability Matrix

| Capability | v11.4 | v11.5 |
|---|---:|---:|
| GitHub read-only observation | Yes | Yes |
| Provider read integration | Yes | Yes |
| External validation replay | Yes | Yes |
| Agent session contract audit | Yes | Yes |
| Human-readable provider observation replay | No | Yes |

## Release Gates

- `provider-observation-replay-audit` passes.
- Replay records include `operator_summary`, `what_was_read`, `why_it_mattered`, `what_changed`, `not_proven`, and `next_action`.
- Replay records link provider read integration, GitHub read-only observation, and external validation replay evidence.
- Replay records do not attempt or authorize external writes.
- `release-state-audit` includes the v11.5 replay gate.

## Value Evidence

Before v11.5, provider-read evidence existed as raw JSON records and audits. After v11.5, the same evidence is available as an operator-readable replay packet that states what was read, why it mattered, and what cannot be concluded.

## Not Proven

v11.5 does not prove provider semantic truth, credential safety, GitHub write safety, production automation safety, market value, productivity gain, or broad adoption.
