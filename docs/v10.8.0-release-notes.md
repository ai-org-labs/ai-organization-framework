# AOF v10.8.0 Release Notes

## What You Can Do Now

You can require a specialist role during Council execution and trust AOF to stop if that role is not actually routable to an actor.

Example: if a game project needs `Game Planner` to decide whether evidence checking is mandatory or optional, AOF no longer lets planning proceed with only Builder and Visionary. The specialist is either joined into the Council plan or execution fails before anything is persisted.

## Capability Delta

NEW:

- Role Routing Fail-Closed Runtime.

UPDATED:

- Council execution now records `actor_ref` per seat.
- Deep-path planning now includes Visionary, Builder, and Guardian by default.
- `council` / `council-exec` accept `--required-role` for specialist seats.

REMOVED:

- Nothing.

## Capability Matrix

| Capability | v10.7.1 | v10.8.0 |
|---|---|---|
| Capability Coverage Gate | post-work output chain audit | still available |
| Council Role Routing | fixed default seats | required specialist roles are routed |
| Missing Specialist Handling | can be caught later by audit | fails closed before Council run persistence |
| Planning Council | Builder plus Visionary in deep-path | Visionary, Builder, Guardian |
| Actor Visibility | role only | role plus `actor_ref` |

## Value Evidence

- `buildCouncilExecutionPlan` joins additional required roles into the plan.
- `council-exec` fails before session persistence when a required role has no actor.
- Role matching accepts equivalent forms such as `game-planner` and `Game Planner`.
- Regression tests cover specialist routing and fail-closed persistence behavior.

## Not Proven

This release does not prove that the routed actor makes the correct domain decision. It proves that AOF cannot silently skip a required role during Council execution.
