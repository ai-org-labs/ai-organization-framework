# AOF v11.8.0 Release Notes

## What You Can Do Now

You can tell whether provider-read evidence is fresh enough to reuse.

Mission Control now exposes provider-read freshness state:

- current
- stale
- expired
- unknown

It also shows whether the runtime may use the evidence as current, must refresh it, must block reuse, or should defer.

## Capability Delta

NEW:

- `PCAP-PROVIDER-READ-FRESHNESS-REFRESH`: provider-read evidence freshness is classified and governed before reuse.

UPDATED:

- `PCAP-PROVIDER-READ-DECISION-REPLAY`: decision replay now has a freshness gate for follow-on work.

REMOVED:

- None.

## Capability Matrix

| Capability | v11.7.0 | v11.8.0 | User-visible change |
|---|---|---|---|
| Provider Read Decision Replay | decision state visible | freshness gate attached | Operators can see whether the decision relies on fresh or stale provider evidence. |
| Provider Read Freshness Refresh | not present | current / stale / expired / unknown visible | Old provider observations cannot be reused silently. |

## Value Evidence

- Before: an accepted provider-read replay could be mistaken for current evidence even if the observation was old.
- After: AOF records freshness status and blocks or requires refresh when evidence is stale.
- Five-minute demo: run `visibility-export` and inspect `provider_read_freshness_refresh_projection` in `.aof/artifacts/visibility/current/mission-control.json`.
- Evidence: `.aof/artifacts/product-value-evidence/PVE-TASK-139-V118.json`.

## Runtime / CLI

- Added `provider-read-freshness-refresh-audit`.
- Added provider-read freshness refresh record and audit schemas.
- Added Mission Control `provider_read_freshness_refresh_projection`.
- Integrated the audit into `release-state-audit` for v11.8 and later.
