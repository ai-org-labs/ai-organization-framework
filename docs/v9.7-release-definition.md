# AOF v9.7 Release Definition

## Release Theme

Archmap v0.4.0 Lifecycle Traceability Baseline.

v9.7 makes AOF's architecture/work lifecycle visible through the Archmap v0.4 provider baseline. The release does not vendor Archmap and does not make Archmap the source of truth. AOF remains the governed source of truth; Archmap is an optional projection provider for lifecycle recognition.

Human-facing wording:

> v9.7 lets an operator see how AOF work, requirements, acceptance criteria, decisions, risks, tests, and evidence can be projected into an Archmap lifecycle view without losing the canonical AOF evidence boundary.

## What Users Can Do Now

After v9.7, a user can:

- identify Archmap v0.4.0 as the current AOF architecture-map provider baseline
- trace AOF work evidence to lifecycle concepts: Requirement, Acceptance, Decision, Risk, Test, and Evidence
- inspect the source-of-truth rule before treating a visual architecture view as proof
- use the committed AOF runtime Archmap source as the current architecture projection baseline
- distinguish lifecycle traceability from semantic correctness, rendered UX quality, or provider package availability

## Not Proven Boundary

v9.7 does not prove:

- Archmap rendering quality or Mission Control visual usability
- third-party operator comprehension
- Archmap package availability in every user environment
- semantic correctness of lifecycle relationships
- production provider execution safety
- market value or adoption

## Release Decision

Release only if the operator can distinguish:

- AOF artifact source of truth from Archmap projection
- lifecycle traceability from lifecycle correctness
- provider version adoption from product value
- visual recognition aid from release evidence
