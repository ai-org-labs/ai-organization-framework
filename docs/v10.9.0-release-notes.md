# AOF v10.9.0 Release Notes

## What You Can Do Now

You can ask whether a provider-backed pilot is ready to advance and require AOF to answer from the full governed evidence chain rather than from scattered records or AI confidence.

## Capability Delta

NEW:

- Provider Pilot Execution Readiness.

UPDATED:

- Provider Execution now has a release-level readiness framing that bundles the pre-execution evidence chain.
- Product Value Comprehension now explains why this readiness chain matters to an operator.
- Capability-First Release now treats provider readiness as a user-visible capability, not an internal audit list.

REMOVED:

- Nothing.

## Capability Matrix

| Capability | v10.8.0 | v10.9.0 |
|---|---|---|
| Role Routing Fail-Closed Runtime | required roles resolve to actors before Council execution | still available |
| Provider Execution | separate governed evidence records exist | readiness is framed as one release-level operator decision chain |
| Product Value Comprehension | release value stated per capability | provider readiness explains what decision becomes easier |
| Release-State Governance | audits existing gates | confirms the readiness chain before provider pilot advancement |

## Value Evidence

- v10.9 release definition states the full provider readiness chain.
- Capability release delta explains the user-visible change.
- Product value evidence states before/after, demo path, reduced operator work, and not-proven boundaries.
- release-state-audit remains the final structural gate.

## Not Proven

This release does not run a live provider, write to GitHub/Jira/Slack/OpenAI, prove credential safety, prove billing safety, or prove provider output correctness. It makes the pre-execution readiness decision explicit and auditable.
