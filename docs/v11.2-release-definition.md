# AOF v11.2 Release Definition

## Release Theme

First Governed External Provider Read Integration.

v11.2 proves that AOF can read a real external provider through a bounded read-only adapter and persist the observed provider state as auditable runtime evidence.

## What You Can Do Now

An operator can ask AOF to inspect GitHub and get a runtime-backed provider read integration record that shows:

- which external provider was read
- which adapter/resource contract bounded the read
- what provider objects were observed
- what decision or next action was derived
- whether any external write was attempted or authorized
- what is still not proven

## Capability Delta

NEW: Provider Read Integration Proof.

Before v11.2, AOF could observe GitHub and explain the selected task, but the external read itself was mostly a one-off observation packet.

After v11.2, AOF treats the external provider read as a governed runtime integration with adapter/resource refs, provider outputs, no-write boundaries, and a dedicated audit gate.

## Release Boundary

This release does not prove provider writes, live automation, production safety, credential safety, provider semantic truth, market value, or broad third-party adoption.

It proves a bounded read-only GitHub integration path and makes that path release-auditable.

## Required Gate

- `provider-read-integration-audit` passes.
- `release-state-audit` includes the v11.2 gate.
- `organization-verify` passes.
- `npm test` passes.
- `npm run smoke` passes.
