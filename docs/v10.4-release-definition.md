# AOF v10.4 Release Definition

## Release Theme

External Value Reproduction Evidence Package.

v10.4 does not claim that an external operator has already reproduced AOF value. It defines the evidence package an external operator can use to reproduce and report whether AOF value is understandable and observable outside self-hosting.

Human-facing wording:

> v10.4 gives an external reviewer a concrete package for checking AOF value: what scenario to run, what value should be visible, what evidence to capture, and what result would count as accepted, rejected, or inconclusive.

## What Users Can Do Now

After v10.4, a user can:

- hand an external operator a bounded AOF value reproduction package
- distinguish internal self-hosting evidence from external reproduction evidence
- require a scenario, expected value, observation steps, evidence fields, and verdict before claiming value reproduction
- record accepted, rejected, inconclusive, or context-mismatched external value results
- block product claims when external value has not yet been reproduced

## Capability Delta

NEW:

- `PCAP-EXTERNAL-VALUE-REPRODUCTION-PACKAGE`: AOF can prepare a bounded package for external operators to reproduce and report user-visible value.

UPDATED:

- `PCAP-THIRD-PARTY-VALIDATION-CONTRACT`: validation now has a concrete value-reproduction evidence package to run.
- `PCAP-PRODUCTION-EXECUTION-AUTHORIZATION-MODEL`: production execution remains blocked until external value and safety evidence exist.
- `PCAP-EXTERNAL-RUNTIME-PRODUCTIZATION`: productization can now separate internal capability from externally reproduced value.

REMOVED:

- None.

## Reproduction Package Contract

A value reproduction package must include:

- scenario: the exact user-facing workflow to inspect
- expected value: what the operator should be able to do or understand
- setup steps: how to install or inspect the release
- observation steps: what to run or read
- evidence fields: screenshots, commands, notes, timestamps, and blocker observations
- verdict fields: accepted, rejected, inconclusive, context-mismatched
- loss boundary: what failed reproduction means and what must not be claimed
- governance trigger: when to reopen product value or capability comprehension work

## Not Proven Boundary

v10.4 does not prove:

- completed external reproduction
- third-party validation completion
- market value or external adoption
- live provider execution
- provider write safety
- production safety

## Release Decision

Release only if AOF makes it harder to confuse:

- reproducible value package with completed external reproduction
- external operator scenario with market proof
- structural release evidence with user-visible value validation
- internal self-hosting success with third-party acceptance
