# AOF v10.7.0 Release Notes

## What You Can Do Now

You can ask AOF to block build/release-critical work unless the required expertise is actually assigned and evidenced.

Before v10.7, AOF could prove that roles, tasks, and artifacts existed, but it could still miss that required specialists were not assigned to the work.

After v10.7, AOF can run capability-coverage-audit and fail when a work item needs Builder + Guardian, game design, UX, QA, or other required skills but only a nominal role or an incomplete actor chain exists.

## Capability Delta

NEW:

- PCAP-CAPABILITY-COVERAGE-GATE: Build/release-critical work can be gated on complete role, skill, actor, output, evidence, acceptance, and Council follow-up coverage.

UPDATED:

- Work Readiness: readiness no longer stands alone for v10.7+; capability coverage is a separate release-state gate.
- Skillful Actor Runtime: actor skill packet/evaluation/gate evidence is now consumed by release-critical coverage audit.

## Value Evidence

- AOF now rejects release-critical work when required roles or skills are declared but not connected to concrete actor skill packets.
- AOF now rejects nominal Builder-only execution when the work needs Guardian verification or other specialist coverage.
- AOF now checks that actor assignment evaluations are selected and execution gates are allowed before the work can count as covered.
- AOF now requires Council review evidence, and risk/missing-skill Council notes must preserve follow-up task references instead of disappearing into prose.
- The v10.7 self-hosting example is TASK-127, where Builder, Guardian, and Visionary coverage is connected through work item goal, actor skill packet, assignment evaluation, execution gate, Council review, and release-state audit.

## Runtime Changes

- Added capability-coverage-audit.
- Added schemas/aof-capability-coverage-audit.schema.json.
- Integrated the audit into release-state-audit for v10.7.0 and later.
- Added negative acceptance tests for missing role/skill assignment and missing Council follow-up tasks.

## Boundary

This is a coverage gate, not a claim that the actor judgment is semantically correct. Human review, playtest, domain expert review, and QIF truth evaluation remain necessary where the work outcome depends on real user comprehension or market truth.
