# AOF v10.1.0 Release Notes

## What You Can Do Now

v10.1 gives AOF a third-party operator validation contract. An operator can now see what external validation must prove before AOF external runtime claims can move beyond self-hosting evidence.

This is not completed third-party validation. It is the contract for collecting it.

## Capability Delta

NEW:

- `PCAP-THIRD-PARTY-VALIDATION-CONTRACT`: define what external operators must verify before AOF claims third-party validation.

UPDATED:

- `PCAP-EXTERNAL-RUNTIME-PRODUCTIZATION`: productization now requires external validation boundaries.
- `PCAP-PRODUCTION-READINESS-REVIEW`: readiness feeds the validation contract.
- `PCAP-PRODUCT-VALUE-COMPREHENSION`: release value must state whether evidence is self-hosting or third-party.

REMOVED:

- None.

## Capability Matrix

See `docs/aof-capability-matrix.md` for the version-by-capability table.

## Before / After

Before v10.1, AOF had a productization decision but not a clear contract for outside validation.

After v10.1, AOF can say exactly what a third-party operator must reproduce, understand, accept, reject, or mark as unproven.

## Five-Minute Demo

1. Read `docs/v10.1-release-definition.md`.
2. Check the Third-Party Validation Contract section.
3. Run `node ./src/cli.js release-state-audit --project .`.
4. Confirm v10.1 does not claim completed third-party validation.

## Value Evidence

- Operators no longer have to infer what counts as external validation.
- AOF separates self-hosting proof from third-party proof.
- Future validation results have a concrete acceptance shape.

## Not Proven

v10.1 does not prove completed third-party validation, market value, external adoption, live provider execution, production safety, or permission for external writes.
