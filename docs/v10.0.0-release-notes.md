# AOF v10.0.0 Release Notes

## What You Can Do Now

v10.0 lets an operator see AOF's Council-backed productization decision for external runtime: advance it as a product-grade candidate surface, while keeping live provider execution authorization, third-party validation, and market proof explicitly out of scope.

## Capability Delta

NEW:

- `PCAP-EXTERNAL-RUNTIME-PRODUCTIZATION`: decide whether external runtime should advance as a product-grade candidate surface.

UPDATED:

- `PCAP-PRODUCTION-READINESS-REVIEW`: v9.9 readiness evidence now feeds the productization decision.
- `PCAP-PROVIDER-EXECUTION`: live execution remains blocked, but product direction is explicit.
- `PCAP-PRODUCT-VALUE-COMPREHENSION`: release value is stated as user capability and proof boundaries.

REMOVED:

- None.

## Capability Matrix

See `docs/aof-capability-matrix.md` for the version-by-capability table.

## Before / After

Before v10.0, AOF had readiness evidence but no explicit productization decision.

After v10.0, AOF states the decision: external runtime may advance as a product-grade candidate, but cannot claim third-party validation or live execution authorization.

## Five-Minute Demo

1. Read `docs/v10.0-release-definition.md`.
2. Run `node ./src/cli.js release-state-audit --project .`.
3. Confirm the v9.x evidence gates pass structurally.
4. Confirm v10.0 still refuses to claim production authorization, third-party validation, or market proof.

## Value Evidence

- Operators no longer have to infer whether external runtime is productized from many release notes.
- AOF now states productization direction and remaining validation gaps in one place.
- The next releases are sequenced around external validation, provider pilot selection, and authorization.

## Not Proven

v10.0 does not prove semantic truth, market value, third-party acceptance, provider credential safety, billing safety, rollback success in production, or permission for live external writes.
