# AOF v11.9 Release Definition

## What You Can Do Now

Operators can replay tool governance decisions from agent sessions in Mission Control.

Before v11.9, Mission Control showed that agent-session tool calls existed, but an operator still had to open raw session artifacts to tell whether each tool call was allowed, denied, review-required, risky, external-write, or dangerous.

After v11.9, AOF projects recorded tool-call governance into a dedicated Mission Control surface: `tool_governance_replay`.

## Capability Delta

NEW:

- `PCAP-TOOL-GOVERNANCE-REPLAY`: AOF can summarize recorded session tool calls by governance decision, risk class, and approval boundary.

UPDATED:

- `PCAP-AGENT-SESSION-OBSERVABILITY`: session observability now feeds operator-facing tool governance replay instead of exposing raw event lists only.

REMOVED:

- None.

## Release Gates

1. Mission Control includes `tool_governance_replay`.
2. Tool replay is derived from canonical agent-session `tool_call` events.
3. Replay exposes allowed, denied, review-required, unknown, risky, external-write, and dangerous counts.
4. Replay keeps not-proven boundaries visible.
5. `release-state-audit`, `organization-verify`, `visibility-export`, tests, and smoke pass.

## Boundaries

This release proves recorded tool-call governance is visible in Mission Control.

It does not prove semantic truth, model correctness, credential safety, provider behavior, production execution safety, or that unrecorded tool calls did not occur.
