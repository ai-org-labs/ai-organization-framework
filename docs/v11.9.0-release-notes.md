# AOF v11.9.0 Release Notes

## What You Can Do Now

You can see how recorded AI tool calls were governed.

Mission Control now exposes a Tool Governance Replay surface showing:

- allowed tool calls
- denied tool calls
- review-required tool calls
- unknown governance decisions
- risky calls
- external-write calls
- dangerous calls

## Capability Delta

NEW:

- `PCAP-TOOL-GOVERNANCE-REPLAY`: recorded session tool calls are classified into operator-visible governance decisions and risk classes.

UPDATED:

- `PCAP-AGENT-SESSION-OBSERVABILITY`: session streams now power a replay view, not only a raw event list.

REMOVED:

- None.

## Capability Matrix

| Capability | v11.8.0 | v11.9.0 | User-visible change |
|---|---|---|---|
| Agent Session Observability | tool calls listed | tool calls governed and counted | Operators can see whether tool calls were allowed, denied, risky, or review-required. |
| Tool Governance Replay | not present | visible in Mission Control | Raw session streams are no longer required for first-pass tool governance review. |

## Value Evidence

- Before: an operator had to open raw agent-session JSON to understand tool-call approval and safety status.
- After: Mission Control summarizes tool-call governance decisions and risk classes in one projection.
- Five-minute demo: run `visibility-export` and inspect `tool_governance_replay` in `.aof/artifacts/visibility/current/mission-control.json`.
- Evidence: `.aof/artifacts/product-value-evidence/PVE-TASK-141-V119.json`.

## Runtime / CLI

- Added Mission Control `tool_governance_replay`.
- Extended the Mission Control schema with explicit replay counts and replay items.
- Updated the Mission Control viewer to show tool governance replay under agent-session evidence.
- Added regression coverage in `test/runtime-situation.test.js`.

## Not Proven

v11.9 does not prove semantic truth, model correctness, credential safety, provider behavior, production execution safety, or that unrecorded tool calls did not occur.
