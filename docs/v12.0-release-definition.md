# AOF v12.0 Release Definition

## What You Can Do Now

Operators can review provider-backed decision evidence from one governed Decision Console before any external write path is considered.

Before v12.0, Mission Control showed provider decision replay, freshness, runtime safety, and tool governance as separate surfaces. An operator still had to mentally join them to answer: "Should this provider-backed decision advance, defer, reopen, or stop?"

After v12.0, AOF projects those surfaces into `provider_backed_operator_decision_console`.

## Capability Delta

NEW:

- `PCAP-PROVIDER-BACKED-OPERATOR-DECISION-CONSOLE`: AOF can summarize provider-read decision state, freshness, tool governance, external runtime safety, approval boundary, rollback boundary, and no-autonomous-write boundary in one read-only operator surface.

UPDATED:

- `PCAP-PROVIDER-READ-DECISION-REPLAY`: decision replay now feeds an explicit operator Go/No-Go console.
- `PCAP-PROVIDER-READ-FRESHNESS-REFRESH`: freshness status now participates in the operator decision boundary.
- `PCAP-TOOL-GOVERNANCE-REPLAY`: tool governance now participates in provider-backed operator decision review.

REMOVED:

- None.

## Release Gates

1. Mission Control includes `provider_backed_operator_decision_console`.
2. The console derives from provider decision replay, freshness refresh, external runtime safety, and tool governance replay.
3. The console exposes proposed action, operator question, recommended Go/No-Go, evidence refs, approval boundary, rollback boundary, and no-autonomous-write boundary.
4. The console remains read-only and does not authorize provider writes.
5. `release-state-audit`, `organization-verify`, `visibility-export`, tests, and smoke pass.

## Boundaries

This release proves provider-backed decision evidence is visible in one operator decision surface.

It does not prove provider truth, semantic truth, credential safety, billing safety, market value, production execution safety, or autonomous external write authority.
