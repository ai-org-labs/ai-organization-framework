# AOF v11.0.0 Release Notes

## What You Can Do Now

You can ask AOF to look at the real GitHub repository in read-only mode and choose the next most important task with Japanese, evidence-backed reasoning and a clear Go/No-Go boundary.

## Capability Delta

NEW:

- GitHub Read-Only Observation Proof.

UPDATED:

- Release-State Governance now requires the GitHub read-only observation audit for v11.0 and later.
- Capability-First Release now treats provider observation as a user-visible decision capability, not just an internal audit.

REMOVED:

- Nothing.

## Capability Matrix

| Capability | v10.9.0 | v11.0.0 |
|---|---|---|
| Provider Pilot Execution Readiness | provider pilot readiness is framed as one evidence chain | still available |
| GitHub Read-Only Observation Proof | not available | AOF can read GitHub state and select a next task with evidence and no-write boundary |
| Release-State Governance | validates provider readiness gates | also validates GitHub read-only observation proof |

## Value Evidence

- The operator no longer has to manually compare latest release, open issues, open PRs, Actions state, and roadmap before asking “what is next?”
- AOF records the observation boundary so read-only inspection is not confused with GitHub write permission.
- The selected task is stated in Japanese with evidence and human next action.

## Not Proven

This release does not create issues, create pull requests, push commits, mutate workflows, read secrets, or prove external provider execution. It proves a bounded read-only observation and task-selection contract.
