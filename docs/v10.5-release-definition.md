# AOF v10.5 Release Definition

## Release Theme

Provider-Backed Work Lifecycle Product Surface.

v10.5 does not execute against a real provider. It gives operators a user-facing lifecycle surface for understanding how AOF work moves from Need to external-provider readiness, evidence, Council judgment, and blocked next action.

Human-facing wording:

> v10.5 lets a user see the whole provider-backed work lifecycle in one product story: what starts the work, which provider is involved, what evidence is required, who approves it, where execution is blocked, and what must happen next.

## What Users Can Do Now

After v10.5, a user can:

- inspect a provider-backed work lifecycle without reading raw runtime JSON
- see where Need, Discovery, Need Validation, planning, provider candidate, authorization, evidence, Council review, and next action fit together
- distinguish product surface from live provider execution
- identify which gates block a provider-backed task from moving forward
- hand the lifecycle surface to an operator as a product explanation of AOF external work

## Capability Delta

NEW:

- `PCAP-PROVIDER-BACKED-WORK-LIFECYCLE-SURFACE`: AOF can explain provider-backed work as a user-facing lifecycle from Need to blocked/ready next action.

UPDATED:

- `PCAP-EXTERNAL-VALUE-REPRODUCTION-PACKAGE`: external reviewers can use the lifecycle surface as the scenario context.
- `PCAP-EXTERNAL-PROVIDER-PILOT-SELECTION`: selected provider pilot now appears in the lifecycle story.
- `PCAP-PRODUCTION-EXECUTION-AUTHORIZATION-MODEL`: authorization gates are positioned inside the lifecycle.

REMOVED:

- None.

## Lifecycle Surface Contract

The surface must show these stages:

1. Need: what triggered the work
2. Discovery or evidence input: what upstream evidence exists
3. Need Validation: whether the work should exist
4. Planning: what task and scope were selected
5. Provider candidate: which provider is involved and why
6. Authorization: which authority, approval, budget, rollback, incident, stop, reproduction, and adapter gates are required
7. Evidence: what proof exists and what is missing
8. Council review: who judged the current state
9. Current blocker: why execution cannot proceed yet
10. Next action: the smallest governed next move

## Not Proven Boundary

v10.5 does not prove:

- live provider execution
- provider write safety
- production safety
- completed provider integration
- external adoption or market value
- third-party validation completion

## Release Decision

Release only if AOF makes it harder to confuse:

- product lifecycle surface with provider execution
- provider candidate with provider integration
- authorization gates with production safety proof
- internal lifecycle explanation with external adoption evidence
