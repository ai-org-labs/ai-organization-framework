# AOF v10.6 Release Definition

## Release Theme

Third-Party Validation Result Ingestion.

v10.6 does not claim that third-party validation has already been completed. It defines how an external operator result is accepted, normalized, classified, linked to capability claims, and escalated into governance.

Human-facing wording:

> v10.6 gives AOF a way to take an external reviewer result and turn it into governed evidence: accepted, rejected, inconclusive, or context-mismatched, with links to the capability being judged and the follow-up decision required.

## What Users Can Do Now

After v10.6, a user can:

- ingest a third-party validation result without treating it as automatic approval
- classify the result as accepted, rejected, inconclusive, or context-mismatched
- link the result to the capability and release claim it evaluates
- escalate low-confidence, conflicting, rejected, or context-mismatched results to Council review
- block stronger product claims until external results are ingested and reviewed

## Capability Delta

NEW:

- `PCAP-THIRD-PARTY-VALIDATION-RESULT-INGESTION`: AOF can normalize and govern third-party validation results against capability claims.

UPDATED:

- `PCAP-THIRD-PARTY-VALIDATION-CONTRACT`: the contract now has a defined result ingestion path.
- `PCAP-EXTERNAL-VALUE-REPRODUCTION-PACKAGE`: reproduction results now have a target ingestion model.
- `PCAP-PROVIDER-BACKED-WORK-LIFECYCLE-SURFACE`: lifecycle claims can point to ingested external validation status.

REMOVED:

- None.

## Ingestion Contract

A third-party validation result must include:

- result id and recorded timestamp
- external operator identity or anonymized reviewer category
- reviewed release and capability ids
- scenario or reproduction package reference
- evidence refs supplied by the reviewer
- verdict: accepted, rejected, inconclusive, or context-mismatched
- confidence and uncertainty notes
- observed blockers or comprehension failures
- governance trigger and Council routing
- not-proven boundary

## Not Proven Boundary

v10.6 does not prove:

- actual external validation results exist
- third-party validation completion
- external adoption or market value
- live provider execution
- provider write safety
- production safety

## Release Decision

Release only if AOF makes it harder to confuse:

- ingestion contract with ingested external result
- ingested result with automatic approval
- accepted reviewer result with market proof
- structural validation with semantic truth
